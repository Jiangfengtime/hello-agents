# 用一个翻译例子走完 Transformer 的完整流程

## 1. 先看全程：模型究竟要完成什么

输入一句英文，输出一句中文。原始 Transformer 将这个任务分成两部分：

```text
英文：I love cats
       │
       ▼
   Encoder：把英文各位置处理成带上下文的向量
       │
       └──────────────┐
                      ▼
中文前缀：<开始> → Decoder：预测下一个中文 Token
中文前缀：<开始> 我 → Decoder：再预测下一个 Token
                      ⋮
最终输出：我 爱 猫 <结束>
```

**编码器处理输入序列，解码器利用输入信息和已生成的目标序列，逐步预测下一个 Token。** 这里为了讲清主线，假设 `I`、`love`、`cats`、`我`、`爱`、`猫`各是一个 Token；真实分词器可能把它们切成不同的片段。

这里有两条边界需要先讲清：

1. 下文的“翻译成我爱猫”假设模型**已经通过翻译数据训练好**。仅有 Transformer 网络结构，并不自动具有翻译能力。
2. 项目的 [`Transformer.py`](../../code/chapter3/Transformer.py) 实现的是前向计算和随机输入演示，返回各位置的 logits；源码没有分词器、训练循环，也没有“反复取最后一个位置、选词、追加”的生成循环。下文会同时标出**源码已实现的计算**和**完整应用还需补上的步骤**。

## 2. 文字如何进入编码器

### 2.1 Token 化与嵌入

模型先把文本切为 Token，再查出各 Token 的 ID。例如：

```text
I          love       cats
↓          ↓          ↓
ID 17      ID 42      ID 86
```

ID 本身只是索引。嵌入层会把每个 ID 映射为一个可以计算的向量：

```text
I     → [0.2, 0.5, ...]
love  → [0.7, 0.1, ...]
cats  → [0.3, 0.9, ...]
```

嵌入向量是训练得到的。若隐藏维度为 `d_model`，这三个向量组成形状为 `[3, d_model]` 的矩阵；实际处理一批句子时还会增加批次维度。

如果一次处理 `B` 句，且每句源序列补齐为 `S` 个 Token，编码器收到的 ID 张量形状是 `[B, S]`，查嵌入后的形状是 `[B, S, d_model]`。项目用 ID `0` 表示填充位，因此生成的 `src_mask` 会使注意力忽略这些补齐位置。我们的句子只有三个真实 Token，可暂时令 `B=1`、`S=3`，不需要补齐。

### 2.2 加入位置信息

`I love cats` 和 `cats love I` 使用相同的 Token，却表达不同的意思。因此，原始 Transformer 为每个位置加入位置编码：

```text
输入表示 = Token 嵌入 + 位置编码

I     的嵌入 + 位置 0 的编码
love  的嵌入 + 位置 1 的编码
cats  的嵌入 + 位置 2 的编码
```

这里的“加”是**同维度向量逐元素相加**：例如 `[0.2, 0.4] + [0.0, 1.0] = [0.2, 1.4]`。位置从 0 开始编号；同一个 Token 出现在不同位置，就会与不同的位置向量相加。第三章展示的是原始 Transformer 的正弦、余弦编码。想看具体数字、公式、张量形状和项目实现，可读[架构原理详解中的位置编码小节](08-Transformer架构原理详解.md#32-为什么需要位置信息)。

![位置编码生成与向量相加示意图](../images/3-figures/position-encoding-illustration.svg)

## 3. 编码器如何处理英文

编码器不是只把每个 Token 单独转换一次。它要让每个位置的表示结合句子中的其他位置。

### 3.1 自注意力：从相关位置汇总信息

以处理 `love` 为例，编码器会计算 `love` 应当从 `I`、`love` 和 `cats` 各取多少信息：

```text
当前处理：love

参考 I       → 权重 0.25
参考 love    → 权重 0.30
参考 cats    → 权重 0.45
```

上面的权重只是示意。编码器中的自注意力通常可以参考输入句子的全部位置，包括当前位置后面的 Token。`I` 和 `cats` 的位置也会分别计算自己的注意力结果。

注意力通过三组可学习的线性投影得到 `Q`、`K`、`V`：

```text
Q = XW_Q    当前各位置拿什么特征去匹配
K = XW_K    各位置提供什么特征供匹配
V = XW_V    各位置提供什么内容供汇总
```

处理 `love` 时，用它的 `Q` 和各位置的 `K` 计算分数，经过缩放和 Softmax 得到权重，再按权重对各位置的 `V` 求和。矩阵形式为：

```text
Attention(Q, K, V) = softmax(QKᵀ / √d_k)V
```

其中 `d_k` 是每个注意力头中 `K` 向量的维度。除以 `√d_k` 是为了控制分数的尺度。**这里的注意力权重描述信息如何汇总，不是“下一个词是什么”的输出概率。**

把上面的抽象步骤缩成一个能手算的小头：假设 `Q(love)=[1,0]`，三个位置的 `K` 分别是 `[1,0]`、`[0,1]`、`[1,1]`，`d_k=2`。点积并除以 `√2` 后，分数约为 `[0.707, 0, 0.707]`；Softmax 后权重约为 `[0.401, 0.198, 0.401]`。若对应 `V` 也恰好是 `[1,0]`、`[0,1]`、`[1,1]`，则汇总结果为：

```text
0.401 × [1,0] + 0.198 × [0,1] + 0.401 × [1,1]
≈ [0.802, 0.599]
```

这些向量是为了展示运算而人为设定的，并非英文词的真实表示。`[0.802, 0.599]` 也只是**一个头在一个位置**算出的结果；`I`、`cats` 各自也会计算，多个头的结果还会合并并经过后续层。完整手算过程见[架构原理文档的注意力小节](08-Transformer架构原理详解.md#43-手算一个位置分数怎样变成新向量)。

### 3.2 多头注意力：并行计算多组关系

一组 Q、K、V 产生一个注意力头。多头注意力使用多组投影，各头分别计算，再合并结果：

```text
输入向量
   ├── 头 1 的注意力结果 ┐
   ├── 头 2 的注意力结果 ├── 拼接、线性投影 → 输出
   └── 头 3 的注意力结果 ┘
```

这样模型可以在不同的表示空间中汇总信息。不要把每个头机械地解释成一种固定语法功能：头的实际作用来自训练，可能比“一个头专管指代”复杂得多。

### 3.3 前馈网络、残差连接和层归一化

多头注意力之后，每个位置的向量还会经过同一组参数的前馈网络（FFN）。注意力负责在位置之间汇总信息；FFN 独立加工每个位置已经获得的表示。

一个原始 Transformer 编码器层可以简化为：

```text
输入
  ↓
多头自注意力
  ↓
残差相加 + 层归一化
  ↓
逐位置前馈网络
  ↓
残差相加 + 层归一化
  ↓
输出
```

残差连接把子层输入直接加回输出，帮助深层网络中的信息和梯度传递；层归一化帮助稳定数值尺度和训练。真实模型会堆叠多层编码器。最终输出仍然是**每个英文位置一个向量**，只不过这些向量已经包含上下文信息：

```text
encoder_output = [I 的上下文表示, love 的上下文表示, cats 的上下文表示]
```

以 `B=1`、`S=3`、`d_model=512` 为例，编码器输入嵌入和最终输出的形状都是 `[1, 3, 512]`。向量的**数值内容**已被注意力和 FFN 改写，但 Token 位置的数量没有变。解码器稍后会把这三个位置的输出当成可参考的英文信息。

## 4. 解码器如何生成第一词“我”

解码器开始时还没有中文内容，因此输入一个特殊的 `<开始>` Token。它同样先经过嵌入和位置信息，再进入解码器层。

原始 Transformer 的一个解码器层主要有三部分：

```text
目标序列当前前缀
       ↓
掩码自注意力：参考已经出现的目标 Token
       ↓
交叉注意力：参考编码器的英文输出
       ↓
前馈网络：加工当前位置的表示
       ↓
输出
```

这些子层周围也有残差连接和层归一化。

### 4.1 掩码自注意力：利用已生成的中文

解码器必须按顺序生成中文。当前若只生成了 `<开始> 我`，它不能在预测后续内容时提前看到尚未生成的“爱”和“猫”。因果掩码限制每个位置只关注自己及之前的位置：

| 当前位置 | 自注意力可参考的位置 |
| --- | --- |
| `<开始>` | `<开始>` |
| `我` | `<开始>`、`我` |
| `爱` | `<开始>`、`我`、`爱` |

实现时，未来位置的注意力分数在 Softmax 前被设为负无穷或足够大的负数，Softmax 后这些位置的权重为 0。

训练时可以一次放入完整目标前缀 `['<开始>', '我', '爱', '猫']`。对四个位置，因果掩码的可见关系是：

```text
行 = 当前处理的位置；列 = 能否读取的目标位置

             <开始>  我  爱  猫
<开始>          1    0   0   0
我              1    1   0   0
爱              1    1   1   0
猫              1    1   1   1
```

例如模型在 `<开始> 我` 对应的位置预测“爱”时，该位置只能利用 `<开始>` 和“我”的信息，无法从目标序列后面的“爱”“猫”偷看答案。项目还把目标填充位的 Mask 与这个下三角 Mask 合并；本例没有填充位，表格只画了因果部分。

### 4.2 交叉注意力：参考英文

只看已生成的中文还不够，解码器还要知道自己在翻译什么。交叉注意力让解码器参考编码器的输出：

```text
Q：来自解码器当前位置的表示
K、V：来自编码器对 I、love、cats 的输出
```

因此，两种注意力处理的是两个不同问题：

```text
掩码自注意力：目标语言中已经写了什么？
交叉注意力：源语言句子提供了什么信息？
```

假设当前目标前缀是 `<开始> 我`，解码器已有两个目标位置，编码器有三个英文位置。交叉注意力的分数矩阵在每个头中是 `2 × 3`：

```text
                    英文源位置
                 I   love  cats
目标 <开始>      ·     ·     ·
目标 我          ·     ·     ·
```

每一行用一个目标位置的 Q 分别与三个英文位置的 K 匹配，然后从三个英文位置的 V 中汇总信息。源码调用 `self.cross_attn(x, encoder_output, encoder_output, src_mask)`，所以 Q 来自解码器 `x`，K 和 V 都来自编码器输出。若英文句子因批处理被补齐，`src_mask` 还会阻止交叉注意力读取填充位置。

### 4.3 输出层：得到下一个 Token 的概率

经过解码器各层后，最后位置的向量被映射为词汇表中每个候选 Token 的分数（logits），再经过 Softmax。第一次预测的结果可能是：

```text
我：0.80
你：0.10
猫：0.03
其他：0.07
```

概率加起来为 1。生成策略选出一个 Token；在这个例子中假设选出“我”。注意，生成时不一定总选概率最高的 Token，也可以按指定策略采样。

与代码对齐时，解码器本身先输出一个向量，`Transformer.final_linear` 才把它映射成**目标词表大小**的 logits。项目的 `forward` 返回 logits，不直接返回概率；上面的概率是对 logits 另做 Softmax 后的教学示例。若目标前缀长度为 `T`，返回形状是 `[B, T, 目标词表大小]`。生成下一词时使用的是**最后一个目标位置**的 logits，即概念上的 `logits[:, -1, :]`。

## 5. 将生成结果接回输入，直到结束

生成“我”后，将它接到解码器已有前缀后面，再预测下一个 Token：

| 轮次 | 解码器已有的目标序列 | 本轮预测出的下一个 Token |
| --- | --- | --- |
| 1 | `<开始>` | `我` |
| 2 | `<开始> 我` | `爱` |
| 3 | `<开始> 我 爱` | `猫` |
| 4 | `<开始> 我 爱 猫` | `<结束>` |

生成 `<结束>` 后，最终结果为“我爱猫”。**编码器在开始时处理英文输入；解码器在生成阶段逐步扩展中文前缀。** 一层内部的多个位置可以用矩阵运算处理，但下一轮要生成什么，仍依赖上一轮选出的 Token。

如果用当前项目的前向接口写一个**概念性**生成循环，核心步骤会是：

```python
# 概念代码：单样本 B=1；模型、词表、分词器必须已准备好
import torch
src_ids = torch.tensor([encode_source("I love cats")], dtype=torch.long, device=device)
tgt_ids = torch.tensor([[BOS_ID]], dtype=torch.long, device=device)
model.eval()                              # 关闭训练态 Dropout 等
with torch.inference_mode():              # 不记录用于反向传播的计算图
    for _ in range(max_new_tokens):
        logits = model(src_ids, tgt_ids)  # [1, 当前目标长度, V]
        next_id = logits[:, -1, :].argmax(dim=-1, keepdim=True)  # [1, 1]
        tgt_ids = torch.cat([tgt_ids, next_id], dim=1)
        if next_id.item() == EOS_ID:
            break
answer = decode_target(tgt_ids[0].tolist(), skip_special_tokens=True)
```

这里采用贪心选择；采样版本见[采样参数详解](11-模型采样参数详解.md)。`encode_source`、`decode_target`、特殊 Token ID、`device` 和模型仍需应用提供；该片段不能直接替代训练与分词器实现。`eval()` 与关闭梯度记录负责不同的事。按当前 `Transformer.forward` 接口，每轮会重新计算编码器；实际推理可以复用编码器结果并缓存注意力的 K/V。达到长度上限也会停止，但不代表已经生成了 EOS 或完成了任务。

## 6. 训练时为什么又能并行计算

生成时未来中文尚不存在，所以需要逐 Token 生成。训练时，正确答案已经存在：

```text
目标文本：我 爱 猫

解码器输入：<开始> 我 爱 猫
训练目标：  我    爱 猫 <结束>
```

因果掩码保证每个输入位置看不到后面的目标 Token。于是模型能在一次计算中同时得到各位置的预测，并分别与正确答案比较：

```text
看到 <开始>       → 学习预测 我
看到 <开始> 我    → 学习预测 爱
看到 <开始> 我 爱 → 学习预测 猫
```

训练程序根据预测误差反向传播，调整嵌入、注意力、FFN 和输出层等参数。这里说的“并行”，指**已知训练序列上的多位置计算**；生成未知结果时通常仍需逐步进行。

完整的训练还需要把英文转成 `src` ID，把中文错位成解码器输入与标签：

| 解码器输入位置 | 对应真实标签 |
| --- | --- |
| `<开始>` | `我` |
| `我` | `爱` |
| `爱` | `猫` |
| `猫` | `<结束>` |

调用 `model(src, tgt_input)` 会一次得到所有目标输入位置的 logits；损失函数比较各位置的 logits 与右侧标签，并对有效位置求损失。程序随后反向传播、更新参数。**项目中的教学代码只到 `model(src, tgt_input)` 这类前向计算**，训练数据、损失函数和优化器都需要另行实现。训练时使用真实目标前缀；实际生成时只能使用模型自己前几轮选出的 Token，这就是两者数据来源上的关键差别。

## 7. 它与大语言模型常用的 Decoder-Only 有何关系

上面讲的是原始 **Encoder–Decoder Transformer**。第三章随后介绍的 GPT 类 **Decoder-Only** 模型，将提示词和生成内容放在同一条序列里，使用因果自注意力逐步预测下一个 Token：

```text
提示词：“今天天气很”
       ↓
Token 化、嵌入、加入位置信息
       ↓
多层因果自注意力 + FFN
       ↓
词表上的下一个 Token 概率分布
       ↓
选择“好”，接到序列后继续预测
```

| 结构 | 原始 Encoder–Decoder | 基础 Decoder-Only |
| --- | --- | --- |
| 独立编码器 | 有，处理源序列 | 没有 |
| 解码器因果自注意力 | 有 | 有 |
| 对编码器输出的交叉注意力 | 有 | 没有 |
| 输入与输出 | 源序列和目标序列分开处理 | 提示词和生成内容在同一序列中 |

“Decoder-Only”不表示模型不会理解输入，而是说它不使用一个单独的编码器来处理提示词。现代模型的实现细节也可能与原始论文不同。

## 8. 把全部流程压缩到一张路线图

```text
原始 Transformer：I love cats → 我爱猫

源文本 ─→ Token ID ─→ 嵌入 + 位置信息
                          │
                          ▼
             多层编码器：自注意力 + FFN
                          │
                     encoder_output
                          │
                          ▼
目标前缀 ─→ 嵌入 + 位置信息 ─→ 多层解码器
                               │ 掩码自注意力：看已有中文
                               │ 交叉注意力：看英文编码结果
                               │ FFN：加工表示
                               ▼
                         词表 logits → Softmax
                               │
                         选出下一 Token
                               │
                    加到目标前缀，直到 <结束>
```

阅读 [第三章原文](../chapter3/第三章%20大语言模型基础.md) 和 [Transformer.py](../../code/chapter3/Transformer.py) 时，可以沿着这条路线追踪每个模块的输入、输出和维度；如果看到 `mask`，先判断它限制的是**目标序列的未来位置**，还是用来忽略填充位置。
