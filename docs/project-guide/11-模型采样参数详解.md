# 模型采样参数详解：Temperature、Top-K 与 Top-P

[返回第一部分学习指南](01-智能体与语言模型基础详解.md) · [先读 Decoder-Only 生成流程](09-Decoder-Only架构详解.md) · [阅读第三章原文](../chapter3/第三章%20大语言模型基础.md)

> 本文展开第三章「模型采样参数」的内容。表中的 Token、分数与概率都是教学示意，不是实际模型输出。这里讨论的是**推理时如何选择下一个 Token**，不是重新训练模型参数。

## 1. 三个参数分别控制什么

模型读完当前前缀，会为词表中的每个候选 Token 输出一个分数（**logit**）。生成程序再把分数变成概率，选择下一个 Token，把它接到前缀后，重复这个过程。

```text
已有前缀 → 模型输出下一 Token 的 logits
         → 调整概率、筛选候选 Token
         → 从剩余候选中选一个 Token
         → 接到前缀，继续下一轮
```

| 参数 | 核心问题 | 主要效果 |
| --- | --- | --- |
| Temperature（温度） | 保留候选时，概率应有多集中？ | 调整概率差距 |
| Top-K | 最多保留概率最高的几个候选？ | 固定候选数量上限 |
| Top-P | 概率从高到低加到多少为止？ | 根据当前分布动态决定候选数量 |

**先记住：温度调分布，Top-K 和 Top-P 筛候选。** 它们不负责「理解问题」或「判断事实是否正确」。

## 2. Temperature：调整概率分布的陡峭程度

### 2.1 为什么从 logit 开始计算

模型先给出一组原始分数 `z₁, z₂, …`，它们可以为负，也不要求加起来等于 1。Softmax 把分数变为概率：

```text
P(i) = exp(zᵢ) / Σⱼ exp(zⱼ)
```

温度 `T > 0` 通常作用于 Softmax 之前的分数：

```text
P(i | T) = exp(zᵢ / T) / Σⱼ exp(zⱼ / T)
```

把每个分数除以同一个正数 `T`，**不会改变原本的高低次序**，但会改变差距在 Softmax 后表现得有多明显。只考虑两个候选时，它们的概率之比也可以写成：

```text
P(i | T) / P(j | T) = exp((zᵢ - zⱼ) / T)
```

当 `T` 变小时，分数差异被放大；当 `T` 变大时，分数差异被压缩。

### 2.2 同一组分数，改变温度

假设三个候选 Token 的 logits 分别为 `A=2、B=1、C=0`。计算结果约为：

| 温度 | A | B | C | 现象 |
| --- | ---: | ---: | ---: | --- |
| `T=0.5` | 0.867 | 0.117 | 0.016 | 更集中，A 几乎占主导 |
| `T=1` | 0.665 | 0.245 | 0.090 | 保持原始 Softmax 分布 |
| `T=2` | 0.506 | 0.307 | 0.186 | 更平缓，B、C 更有机会被抽中 |

因此，正确方向是：**低温度 → 更偏向高概率 Token；高温度 → 更平缓，低概率 Token 的抽中机会增加**。高温度并不意味着模型一定选低概率 Token，只是它们的相对机会增加。

温度只调整一次选择中的分布，不保证答案更准确或更有创造力；整段输出还受提示、模型能力、后续各步抽样、其他处理器等影响。

### 2.3 `T=0` 怎么理解

上面的公式要求 `T > 0`，因此不能直接把 `T=0` 代进去。理论上当 `T` 从正数趋近 0 时，概率逐渐集中到最大 logit 的候选上；实际接口可能把 `temperature=0` 特殊处理为贪心选择，也可能不接受 0。使用具体库或 API 时，应查看它的参数约定。

## 3. Top-K：只保留概率排名前 K 的候选

假设当前分布如下；这是经过 Softmax 得到的一个示意分布：

| 排名 | Token | 原概率 |
| --- | --- | ---: |
| 1 | A | 0.50 |
| 2 | B | 0.25 |
| 3 | C | 0.15 |
| 4 | D | 0.07 |
| 5 | E | 0.03 |

如果设置 `Top-K=2`，就只保留 A、B。C、D、E 在这一步不能被抽中。保留下来的原概率之和是 `0.50 + 0.25 = 0.75`；重新归一化后：

```text
P(A | 前 2 名) = 0.50 / 0.75 ≈ 0.667
P(B | 前 2 名) = 0.25 / 0.75 ≈ 0.333
```

**保留前 K 名，不等于 K 个候选等概率。** 仍可按归一化后的概率抽样。`K=1` 时只剩概率最高的一个候选，在没有其他特殊规则影响的前提下，结果就是该候选。

按前 K 名且明确处理并列值的教学定义，Top-K 的候选**个数固定**（假设词表至少有 K 个候选）：不管某一步前两个候选的概率合起来是 0.95 还是 0.30，`K=2` 都只留两个。这正是它与 Top-P 的关键差别；实际库对并列阈值的例外见 5.2 节。[Hugging Face：生成参数](https://huggingface.co/docs/transformers/main_classes/text_generation)

## 4. Top-P：让候选集合随分布变化

Top-P 也称 **Nucleus Sampling（核采样）**。先按概率从高到低排序，再从第一名开始累加，取**累计概率达到或超过 `P` 的最短前缀**。[核采样原始论文](https://arxiv.org/abs/1904.09751)

仍使用上表，令 `Top-P=0.8`：

| 已纳入候选 | 累计概率 | 是否停止 |
| --- | ---: | --- |
| A | 0.50 | 没到 0.8 |
| A、B | 0.75 | 没到 0.8 |
| A、B、C | 0.90 | 已达到 0.8，停止 |

最终保留 **A、B、C**。第三个候选 C 必须完整保留，不能只取它的 0.05 概率来凑出 0.80。保留集合原来的概率和是 0.90，重新归一化后约为：

```text
P(A | Top-P 集合) = 0.50 / 0.90 ≈ 0.556
P(B | Top-P 集合) = 0.25 / 0.90 ≈ 0.278
P(C | Top-P 集合) = 0.15 / 0.90 ≈ 0.167
```

这里应说「**达到或超过** P」，而非只能说「严格大于 P」：如果 A、B 的概率恰好加到 0.80，就不需要再纳入 C。[Hugging Face：Top-P 定义](https://huggingface.co/docs/transformers/main_classes/text_generation)

Top-P 的候选**数量不固定**。如果模型非常确信第一名（例如它的概率是 0.85，`P=0.8`），只需保留一个；如果分布很平缓，就需要多个候选才能达到 0.8。

## 5. 三者一起使用时会发生什么

假设某个实现先按温度调整分布，再用 Top-K 和 Top-P 筛选：

```text
logits → 按温度缩放 → Softmax 概率
       → Top-K 筛选候选，并在保留集合上重新归一化
       → Top-P 按此时的概率累加并筛选
       → 对剩余候选重新归一化并抽样
```

在这种流程里，温度不仅改变剩余候选之间的抽样概率，还可能改变 Top-P 最终需要多少个候选：分布变尖时，更少的候选就能达到 `P`。

**这是一种具体流程示意，不是所有库和 API 的统一执行顺序。** 不同实现可能对分数处理器、Top-K、Top-P 和归一化采用不同顺序、边界规则或默认值；某些接口甚至不允许同时使用这些参数。参数效果应以所用实现的文档和源码为准。此外，如果选择的是贪心解码而不是随机采样，设置采样参数未必会改变结果。Hugging Face 的 `generate()` 就用 `do_sample` 区分采样与非采样路径。[Hugging Face：生成策略及参数](https://huggingface.co/docs/transformers/main_classes/text_generation)

### 5.1 一个连用的完整数值例子

假设经过温度处理后的五个概率为 `A=0.50、B=0.25、C=0.15、D=0.07、E=0.03`。采用“先 Top-K，再在剩余分布上做 Top-P”的流程，设置 `K=3、P=0.8`：

| 步骤 | A | B | C | D、E |
| --- | ---: | ---: | ---: | --- |
| 原分布 | 0.50 | 0.25 | 0.15 | 0.07、0.03 |
| Top-K 后重新归一化 | 0.5556 | 0.2778 | 0.1667 | 排除 |
| 累计概率 | 0.5556 | 0.8333 | 1.0000 | — |
| Top-P 后最终抽样概率 | 0.6667 | 0.3333 | 排除 | 排除 |

Top-K 后剩余概率总和是 `0.9`，所以先分别除以 `0.9`。Top-P 在 B 处已经达到阈值，保留 A、B；最后再归一化为 `2/3、1/3`。最终仍然可能选中 B。

如果直接在最初分布上计算 Top-P，A+B 只有 `0.75`，要加 C 才达到阈值；将这个集合与原 Top-K 集合相交，会保留 A、B、C，结果不同。因此，**不能笼统地将连用描述为“各自在原分布上筛选后取交集”**。实现可能通过把排除项的 logits 设为负无穷，再 Softmax，来完成等价的归一化，并非一定显式除法。

### 5.2 边界条件与参数不生效的原因

- `T=1` 仅表示不改变 logits 的温度尺度，不意味着关闭 Top-K 或 Top-P。
- 对有限且未屏蔽的 logits，`T→∞` 时趋近均匀分布；`T→0+` 时集中到最大值。如果最大值并列，数学极限并不自动选定其中某一个。
- 正温度缩放不会改变 logits 排名；如果直接做 argmax，温度本身不会改变最大值的位置。低温不代表事实可靠，也不能保证不同服务运行完全一致。
- Top-K 的教学定义是按确定的并列处理规则取前 K 个；具体实现可能保留所有并列第 K 名。比如 Transformers v4.55.4 的阈值筛选会保留等于第 K 大分数的项，因此候选数可能超过 K。[固定版本源码](https://github.com/huggingface/transformers/blob/v4.55.4/src/transformers/generation/logits_process.py)
- `P=1` 通常让 Top-P 本身不再截断，但其他过滤仍可生效。`K=0`、`P=0` 等特殊值是否允许、代表什么，要看接口约定。
- 表格只显示四舍五入后的概率，显示值相加可能略偏离 1；计算时应使用未舍入的值。

## 6. 把常见误解逐一改正

| 常见说法 | 更准确的理解 |
| --- | --- |
| 「温度越低，分布越平缓」 | 温度**越高**越平缓；越低越集中。 |
| 「温度控制候选词的数量」 | 温度主要调整概率差距；若后续接 Top-P，候选数量可能被间接影响。 |
| 「Top-K 从前 K 名中等概率选」 | 只限制候选集合，通常仍按剩余概率抽样。 |
| 「Top-P 的累计概率必须等于 P」 | 只要求达到或超过 P；最后一个 Token 往往使总和超过 P。 |
| 「Top-P=0.8 就一定保留 80% 的词」 | 0.8 指**累计概率质量**，不是词表数量的 80%。 |
| 「温度越低，回答就一定正确」 | 参数只影响选择方式，不会自动验证事实。 |
| 「Top-K、Top-P 总会生效」 | 还要看是否启用采样及具体实现。 |
